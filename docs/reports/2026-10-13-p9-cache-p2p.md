# P-9 (Cache AddAccessible/RemoveAccessible/GetItems consistency) and P2P reachability (ADR-0001 D-7)

Date 2026-10-13, linux-platform-engineer. Inputs for bake-off B-1 (arm b, eager `Cache.GetItems`) and M2 P2P.

## 0. Method and evidence classes

* **LIVE-real**: read-only calls on the real session's a11y bus (`Properties.Get`, `GetState`, `GetChildren`, `GetItems`,
  `GetApplicationBusAddress`). Nothing registered, no `IsEnabled`/`ScreenReaderEnabled` write, nothing killed. Tool:
  `tools/platform-probes/p9live.py`. Orca was already running on this host (`ScreenReaderEnabled=true`).
* **LIVE-private**: a private headless `gnome-shell` + private session bus + private a11y bus + private `at-spi2-registryd`

  (`tools/platform-probes/p9apps/`) and stock Nautilus (GTK4/libadwaita). `tools/platform-probes/p9probe.py` is an AT there
  (registers event listeners, only on the private bus). After each scripted mutation it compares
  *(GetItems snapshot + Cache.Add/RemoveAccessible signals)* with a ground-truth tree walk. The rig is torn down.

### 1.1 Facts that affect any mirror built from `GetItems` + signals

1. **GetItems order is a hash order** (both GTK4 and atk-bridge): children can precede parents. Build the tree in two passes by parent ref.
2. **No sequence number.** Subscribe to `Cache` signals *before* calling `GetItems` and make inserts idempotent by ref. GTK4 additionally suppresses `AddAccessible` while it serialises `GetItems` (`in_get_items`), and `get_parent_context_ref` can realise a parent inside that call that is not in the snapshot (SRC, unobserved race).
3. **`Cache.version` property is not readable on any toolkit** (`InvalidArgs`/`UnknownProperty` on Nautilus, gedit, Shell, Firefox), and the live introspection of GTK4 lists no `Ready` signal. Detect the layout by the `GetItems` reply signature, not by `version`/`Ready`.
4. **GTK4 gates all `Object` events on registered listeners** (`gtk_at_spi_root_has_event_listeners`), including `ChildrenChanged`, `StateChanged` and `defunct`. With zero listeners the test app emitted no `Object` event at all (only `Cache.Add`). atk-bridge keeps its always-on set (see `org.a11y.atspi.Registry.md`). gorca registers listeners, so this only matters in tests and at startup before `RegisterEvent`.
5. **GTK4 emits a spurious `ChildrenChanged:add`** on the *parent* for most property or state updates of a child (observed for checkbox toggle, label text, scale, switch, tooltip-less button). Treat `ChildrenChanged` as "re-list children of this node", never as a delta.
6. **`StateChanged` completeness differs**: GTK4 `sensitive=false` flips `SENSITIVE` but left `ENABLED` set (observed); GTK3 flips both.

## 3. Recommended revalidation policy (feeds B-1)

* **Primary fill = arm (a)/(c), not (b)**, except Shell. A GetItems-based eager fill is complete only for St/Shell and ordinary GTK3 containers.
* **Revalidate-on-read for the focused node, every time**, in parallel with speaking from cache (ADR-0001 M-6 refine): `Name`, `GetState`, `ChildCount` plus the nearest named ancestor chain when the node's role is name-from-content (button, list item, row, cell, menu item, expander, tab). Measured cost: `Properties.Get` p50 0.12-0.15 ms, p99 0.6-1.5 ms; GetItems 307 GTK4 items 13.8 ms (too slow for per-focus, fine for reconcile).
* **GTK4: invalidate the content-derived ancestors of any node that fires `accessible-name`** (parent chain up to the first non-content role), and the `labelled-by` referrers (needs a `GetRelationSet` fetch, cache it).
* **ChildrenChanged = "mark child list dirty"**; refetch lazily on next read, never apply as delta (spurious on GTK4).
* **Liveness**: do not trust `RemoveAccessible` (never emitted by GTK4 for widget removal, and not for detached-but-alive GTK3 widgets). Drop on `StateChanged:defunct`, on `ChildrenChanged:remove` for that child, on `UnknownObject`/`Failed("Not found")`, and on parent generation bump.
* **TTL as a safety net, not a mechanism**: unfocused cached entries older than 30 s are served but marked `maybe_stale`, revalidated by the next read that would speak them. Concretely per toolkit: GTK4 30 s; GTK3 60 s; Shell 60 s; Firefox/Chromium chrome 30 s (document nodes follow the document mirror rules). The atk-bridge 15 s object lease means any `(bus,path)` older than 16 s with no event may be dead on atk-bridge apps; treat `UnknownObject` as normal, not an error.
* **Periodic reconcile** (arm b used as a verifier, off the hot path): `GetItems` every 60 s for the focused app only, diff against the mirror, repair ghosts and unannounced nodes.

## 4. P2P reachability (ADR-0001 D-7)

Mechanism: `org.a11y.atspi.Application.GetApplicationBusAddress` at `/org/a11y/atspi/accessible/root` returns `unix:path=$XDG_RUNTIME_DIR/at-spi2-XXXXXX/socket`; the call lazily creates the socket in the app (`spi_atk_create_socket`, `refs/at-spi2-core/atk-adaptor/bridge.c:947`). libatspi's own client opens it with `dbus_connection_open_private`, with a 2000 ms async deadline for the address call and for `GetItems`, and silently keeps the bus connection on empty/failed reply (`atspi-misc.c:368-448`).

| Toolkit | Reachable? | Evidence | Notes |
|---|---|---|---|
| **GTK3 (atk-bridge)** | Yes | LIVE-real gedit, gnome-terminal, gsd-*; LIVE-private | connect 0.2-0.9 ms; `GetChildren` p50 0.09-0.38 ms P2P vs 0.07-0.16 ms bus (noise; **P2P is not reliably faster**, one gedit run 0.232 vs 0.065 ms, one run 0.135 vs 0.157 ms) |
| **GTK4** | **No** | LIVE-real Nautilus (private) and test app: `UnknownMethod: No such method "GetApplicationBusAddress"`. SRC `gtkatspiroot.c:191` would return the a11y *bus* address (`root->bus_address`), not a socket, and the method is missing from the object's interface info. | Always bus call connection. |
| **gnome-shell (St)** | Yes | LIVE-real `:1.0`: connect 0.94 ms, `GetChildren` p50/p99 0.108/0.337 ms vs bus 0.140/1.088 ms | atk-bridge |
| **Firefox** | Yes | LIVE-real both instances: connect 0.30-0.44 ms, p50 0.042-0.236 ms vs bus 0.066-0.161 ms | atk-bridge |
| **Chromium** | Expected yes (not observed) | SRC `atk_bridge_adaptor_init` | Browser process owns the socket; renderers are not reachable this way. |
| **Qt** | **No** | SRC `atspiadaptor.cpp:222` declares the method in introspection XML but `applicationInterface()` (line 1580) has no handler -> falls to "does not implement" | Always bus. |
| AT clients (Orca) | Returns `""` | LIVE-real: Orca's reply is empty; inferred from `application-adaptor.c:113` (`atspi_is_initialized() ? ""`) | gorca itself is not an app, no issue. |

Fallback behaviour to build in:
* Returns `""`, `UnknownMethod`/`NotSupported`, or connect error (`ENOENT` = stale path, e.g. the app exited) -> mark the app `NoP2P { reason }`, use the bus call connection, retry only on app restart (new unique name).
* `ATSPI_DISABLE_P2P=1` in the app's environment makes it return no address (SRC `bridge.c:956`).
* Observed in the private rig: a **too-long `XDG_RUNTIME_DIR`** (path over the ~107-byte `sun_path` limit) made `dbus_server_listen` fail and the call returned `""` (inferred from `bridge.c:992-1000`; the bridge only `g_warning`s). Real sessions use `/run/user/UID` (short), but tell users of nested/sandboxed layouts.
* The first call executes `mkdtemp` + `listen` on the app's main loop: if that loop is hung the call times out; use the `Startup`-class deadline (suggest 250 ms for the address call and 250 ms for connect; measured connect <= 0.94 ms) and then `NoP2P`. Do not retry in a loop.
* P2P carries only method calls on that connection. Events still arrive via the bus; liveness comes from the broker's `NameOwnerChanged` (the P2P peer has no bus name), plus EOF on the socket -> `Gone` (matches D-7).
* No broker means none of its limits (per-uid quotas, max message size) apply to P2P traffic; our own request deadlines are the only protection against a flooded or hung app, and a hung app's P2P connection blocks only that app's actor.

Security:
* Socket file mode is **0777** but its parent directory `at-spi2-XXXXXX` is **0700**, owned by the user, so reachability is effectively same-uid (LIVE-real: `sock=0o777 dir=0o700` for every atk-bridge app). The a11y bus socket itself is `0770` in a `0700` directory.
* libdbus enforces the peer uid in `new_connection_cb` -> `user_check` (`bridge.c:660`): same uid/euid only; when the app runs as root it accepts the "ancestral uid" (the first non-root ancestor) or uid 0/1. Root-owned apps place the socket directly in `$XDG_RUNTIME_DIR/at-spi2-socket-PID`, **without** the private 0700 subdirectory, so confidentiality then rests on the uid check only.
* P2P bypasses the broker entirely: no broker audit/log, no `Debug.Stats`, no AccessDenied policy, and the peer is anonymous (no unique name). Treat the app's socket path as untrusted input from the app (a malicious same-uid app can return any path): verify it is under `$XDG_RUNTIME_DIR`, a socket, owned by the app's uid (`GetConnectionCredentials` of the bus name) before connecting, and never follow a path outside the runtime directory.
* Both `GetApplicationBusAddress` and `GetItems` register the calling bus name as an AT client in the app's bridge (`spi_atk_add_client`): calling them is observable by the app and starts event emission to us. Harmless for gorca but not "read-only" from the app's point of view.

## 5. Open questions / unverified

* Chromium was not installed: all Chromium statements are SRC. Chrome 4-item figure is from the earlier measurement.
* GTK4 `in_get_items` race (realisation inside `GetItems` not announced) is from source only.
* P2P latency advantage is within noise on this host (RT kernel, other load); needs the B-5 quiet-host run for a verdict. The structural benefit (broker bypass during storms) is untested here.
* Description changes were not compared in the mutation tests (only name, child count, states).
* Qt `GetItems` item layout (children array) from the marshaller header only; no Qt app was available.
* Firefox cache growth rules (when it goes beyond 2 items; an earlier measurement saw 168) are unexplained.
