# ext-gnome-shell as a WASM component (M5 follow-up)

Status: done. The Shell policy runs as a `wasm32-wasip2` component by default; the native build of the
same source is the fallback (ADR-0008 amendment 1). Raw data: `docs/reports/ext-gnome-shell-wasm-data/`.

## What changed

- **A fourth hook, `policy`** (WIT `hooks.policy: func(policy-facts) -> policy-verdict`, Rust
  `Hooks::policy(&PolicyFacts) -> PolicyVerdict`). The Shell's rules are asked at four moments
  (focus, value, activate, showing) and answer silence / value / say / notice / defer. The existing
  `present` hook only covers focus and cannot express `Value` or `Notice`, and a `present` rewrite
  would not be the core's own utterance with the value replaced, so reusing it would have changed
  behaviour. The facts are a record (no node key: the `showing` moment has only a role).
  `AppExt::policy` is a defaulted method of the core trait (returns `None`); `ExtHost` implements it:
  first extension that does not defer wins, a busy / faulted / disabled slot is "no opinion", limit
  2 ms CPU (fuel) with the tight `present` backstop, no speech budget (it is not speculative speech).
- **Reader**: `policy_active` / `decide_policy` replace the five `app_policy` call sites. Order:
  the extension host's `policy` hook for that application, then the native `AppPolicy` if one is
  installed, else `Default`. The profile gate (`verified_shell`) is unchanged.
- **`ext-gnome-shell`**: `crate-type = ["cdylib","rlib"]`, `ext.toml` (`hooks = ["policy"]`,
  `verified_shell = true`, no capabilities), `ShellExtension::policy` over the unchanged `RULES` table,
  `export_extension!`. The old `present` impl (focus only, would double-apply) is removed.
- **Daemon**: `--shell-policy=auto|native` (env `GORCA_SHELL_POLICY`). `auto` loads the component if
  the host did and installs the native adapter only otherwise (they are exclusive, so the gates really
  exercise WASM); the log line `shell policy: ext-gnome-shell WASM component | native build` says
  which. `native` skips loading the component (`ExtHostBuilder::skip`).
- **Packaging**: `cargo xtask build-ext` builds the component (release, no debug info: 71 KB instead
  of 3 MB) and installs `target/{debug,release}/extensions/ext-gnome-shell/{ext.toml,ext_gnome_shell.wasm}`.
  `make ext` is part of `make check` (before `test`) and `make release`. Default directory search in
  `main` only (the library and tests never pick one up): `<exe dir>/extensions`,
  `<exe dir>/../lib/gorca/extensions`, `/usr/local/lib/gorca/extensions`, `/usr/lib/gorca/extensions`;
  `--ext-dir=` (empty) disables. `contrib/systemd/gorca.service` names
  `--ext-dir=<repo>/target/release/extensions`; `tools/install-dev.sh` warns if the component is not
  built. A missing or broken component logs and falls back to the native build.

## Parity

`crates/gorca-daemon/tests/shell_parity.rs`: 4 moments x 44 roles x 3 state sets x 6 names x 2
descriptions x 13 ranges (NaN, infinity, 0..1, 0..100, degenerate included) = 82,368 facts through
(a) the daemon's native `AppPolicy` adapter, (b) the native build behind the extension host,
(c) the component under wasmtime. All three equal on every fact, 0 faults, 0 busy skips; plus
explicit dialog / OSD / banner / stage / window / unnamed-slider cases through the component and a
check that a non-verified "gnome-shell" gets no policy. `desktop.rs` (6 tests, 2 of them the Shell:
banner, OSD) 5x each, interleaved native / WASM: 10/10 runs 6/6 (`data/desktop/summary.txt`; the WASM
run logs `shell policy: ... WASM component`). The unit tests of `ext-gnome-shell` run unchanged against
the native build; `ext-test` gained a `policy` fault-injection trigger and a test that a crashing or
looping policy is "no opinion", resets in < 50 ms and recovers (both backends).

Known, bounded difference: names are clipped to 4096 chars and segments to 2048 by the host
(`MAX_NODE_TEXT_CHARS`, `MAX_SEGMENT_CHARS`) in the component path only; the Shell has no such names.

## Not done / open

- `ext-vte` not ported (another agent is changing terminal focus handling); `--shell-policy` and the
  `policy` hook do not touch it. The Alt+Tab switcher routing is still `AppProfile::speak_selection`
  (a core switch); moving it needs `on_event` over `SELECTED_NOW` and is the next port step.
- `ProtectSystem=strict` in the unit makes `~/.local/state/gorca` read-only: harmless now (the Shell
  extension declares no `settings` capability), but the unit needs `ReadWritePaths=` before any
  extension persists settings.
- The WASM build is compiled by wasmtime at daemon start (about 70 KB, tens of ms, in a blocking task
  before the core starts serving; not separately measured here).
- Not run against a real GNOME Shell (live-session rule): the Shell evidence is the fake Shell in the
  private session (A1/N1, `desktop.rs`) and the probe-derived rule table.
