# M3 live checklist: caret, typing echo, selection, say-all (native text)

Run on the real GNOME 48 desktop with `tools/gorca-toggle.sh` (Super+Alt+G); gorca must be the only screen reader.
Specification: `docs/adr/0007-text-caret-and-typing-echo.md` (what the code does differently is in its changelog).
Keys are the NVDA desktop layout. `gorca` = Insert (or KP_Insert with Num Lock off) or Caps Lock.

Everything below was built against the fake app (`tests/harness/fakeapp.py --scenario text`), which emits the signals
the way GTK does. **No real GTK3, GTK4 or St entry has been run under it yet**; the first three rows of "Open
platform questions" are what this checklist must settle.

## Keys

| Step | Keys | Expected |
|---|---|---|
| Character | Left / Right in an entry | the character the caret lands on (a space says "space", behind the last character "blank"); Home / End say the character at the caret |
| Word | Ctrl+Left / Ctrl+Right | the word the caret lands on |
| Line | Up / Down in a text view; PgUp / PgDn | the line (as wrapped on screen); in a single-line entry the whole text |
| Paragraph, document | Ctrl+Up / Ctrl+Down; Ctrl+Home / Ctrl+End | the paragraph; the line at the caret |
| Boundary | Left at the start, Right at the end, Up on the first line | the unit at the unchanged caret (no silence), within 100 ms |
| Held arrow | hold Right for 3 s | no queue of old characters: speech follows the caret and ends on the last position |
| Typing | letters, digits, punctuation, Space, Return in a text view | each character once, from the key press; Space says "space", Return in a text view "new line"; Return in a single-line entry says "enter" |
| Other layouts | Russian layout, AltGr characters | the character produced, once |
| Erase | BackSpace, Delete, Ctrl+BackSpace | the deleted character (word for Ctrl); never the key name; nothing at the boundary |
| Paste, cut | Ctrl+V, Ctrl+X | the pasted text (up to 256 characters, then "and N more"); the cut text |
| Input method | a CJK or compose-key sequence | the committed text, once |
| Selection | Shift+Right / Left / Down, Ctrl+Shift+Right | "x selected" for what became selected, "x unselected" for what was released; only the change is spoken |
| Select all | Ctrl+A | "all selected, N characters" |
| Collapse | Left or Right with a selection | the unit under the caret, not "unselected" |
| Mouse selection | drag over text | "x selected" (a long one: "N characters selected") |
| Say current | `text.say_char/word/line` (unbound by default: bind them in `gorca.toml`), gorca+Up | the unit at the caret; gorca+Up twice spells the line, three times phonetically |
| Say selection | gorca+Shift+Up | the selected text, or "no selection" |
| Say all | gorca+Down | reads from the caret in sentences; any key stops it at once and leaves the caret at the start of the sentence being read; at the end it stops quietly with the caret at the end |
| Punctuation | gorca+P | cycles none, some, most, all; "some" names `@ # $ % & * + = < > / \ | ~ _` in words and lines |
| Typed words | gorca+3 | on: the word is spoken when the space or punctuation after it is typed |
| Toggle characters | gorca+2 | off: no character echo, no double echo either when it is on again |

## Applications

| App | Check |
|---|---|
| Text Editor (GTK4 `GtkTextView`) | all rows above; a wrapped paragraph reads as screen lines with Up / Down; Ctrl+A, Shift+arrows |
| A GTK4 entry (Settings > Wi-Fi password dialog, Files rename) | typing, BackSpace, Home / End, Shift+Home, Ctrl+A |
| A GTK3 entry (an older app: Evolution, a Firefox-free GTK3 tool such as `gtk3-demo`) | the same; GTK3 sends the text with `text-changed` through atk-bridge |
| GNOME Shell: overview search entry, run dialog (Alt+F2), a login or unlock field | the same; St entries are the ones most likely to send `text-changed` without text or in a different order |
| A password entry (Settings > Wi-Fi, a sudo prompt in a GTK dialog, the lock screen) | **the characters (or bullets) are spoken**, `gorca+F1` and `--bench-present-log` show nothing but `redacted(len=N,h=...)`; `journalctl --user -u ...` and gorca's stderr with `RUST_LOG=trace` hold no typed text |
| Firefox fields (input, textarea, contenteditable) | M3b: all rows above apply; see `docs/plan/checklists/M7b.md` |
| GNOME Terminal | out of scope here (M6): arrows may be silent or double; note only what is new compared with M1 |
| A read-only text (About dialog text, a help view) | arrows read; typing is not echoed as text (generic key echo only) |
| A hung application (SIGSTOP a test app you started yourself) | arrows in it speak nothing for at most 120 ms, the reader stays usable, no other application is delayed |

Anything that speaks twice for one key, speaks the wrong unit, misses a boundary, or stays silent after a key is a bug:
note the application, the key and the toolkit, and run `gorca+F1`.

## Open platform questions (ADR-0007 section 19, to be answered on the real desktop)

1. **V-T1** (GTK3, GTK4, St): in what order do `text-changed:insert` and `text-caret-moved` arrive when typing, does
   `text-changed` carry the text, and is the caret offset right after an input-method commit? A duplicated or missing
   typed character points here: gorca logs the text counters (`caret_absorbed`, `window_dirty`,
   `insert_held_claimed`, `delete_held_claimed`, `inserts_coalesced`, `events_dropped`) and the speech lane's counters at
   info level when it stops.
2. **V-T2** (GTK4 `GtkTextView` wrapped line): does `GetStringAtOffset(LINE)` return the visual line or the logical one?
   Down in a long wrapped paragraph reads either one screen line or the whole paragraph.
3. **V-T4** (IBus, Russian layout): does a commit produce `KeyEvent`s through the Mutter monitor? If it does, each
   composed character is echoed as typed; if not, the commit is spoken from the insert (TE-3). Either way once.
4. **Caps** `speech.caps = "pitch"` (default) cannot raise the pitch yet, so a capital letter sounds like its lower-case
   letter; `caps = "say"` says "cap A". Decide the default after hearing both.

## Gates (automatic)

`bench/e2e/run.sh m3-final --only C1,C1h,C1hs,C2,E1,E1s,E2,S2,SA1,SA2,SA3,SA3a,PW --reader daemon:<abs>/target/release/gorca,--impersonate-orca --reader-env GORCA_M3=1`
(`GORCA_M3_STRICT=1` fails instead of skipping). Strict M1 and M4a gates stay green:
`--only K2,K2s,K3,K4 --reader-env GORCA_M1=1 --reader-env GORCA_M1_STRICT=1` and
`--only R1,R1s,RS --reader-env GORCA_M4=1`.

| Gate | Result on 2026-10-14 (private session, governor performance x16, load 4.5 to 7 from other work on the host) |
|---|---|
| C1 p99 <= 15 ms | 0.73 ms median of 3 (`m3-final5`), one `GetStringAtOffset` per key, `lost` 0 |
| C1h p99 <= 3 ms, 0 IPC | 0.28 ms median of 3, `c1h_ipc_calls` 0, `lost` 0 |
| C1hs, E1s (under L3-50k) | 0.29 ms and 0.35 ms (gate: idle gate plus 1 ms = 4 ms) |
| C2 held Ctrl+Right, 30 Hz, 3 s | `stale_not_cancelled` 0, the last position spoken, 90 of 90 reached the server |
| E1 p99 <= 3 ms | 0.34 ms median of 3 (key emit to SPEAK), `lost` 0, `e2_double` 0 |
| E2, 10,000 actions x 2 (`m3-e2-final2`) | `e2_missing` 0, `e2_double` 0, `e2_keyname` 0, `e2_wrong` 0 (Latin, Cyrillic, Space, BackSpace, paste, keyless commit); the reader's counters agreed with the harness (8,018 typed keys echoed 8,018 times, 1,711 BackSpaces spoken 1,711 times; 9 inserts and 2 deletes had overtaken their key and were claimed by it) |
| S2 p99 <= 15 ms | 1.04 ms median of 3 (includes the selection fetch and the fake app's reply) |
| SA1 p99 <= 15 ms | 1.05 ms median of 3 |
| SA2 | 2,500 chunks x 3, `sa2_ahead_ratio` 1.0, gap between the server's END and the next SPEAK p99 0.16 ms (see ADR-0007 changelog: the clients hold one utterance at the server) |
| SA3 | key to speech cancel p99 0.40 ms (gate 2 ms); key to the caret placed p99 0.76 ms (gate 50 ms); the caret lands on a line start every time |
| SA3a | stop say-all with an arrow: the app handles the key from the reading position; gorca never moves the caret back (`sa3a_caret_moved_back` = 0). SA3 no longer has a caret-latency metric: the caret follows the reading |
| PW | 0 occurrences of the typed string or of two 8-character pieces of it in the presentation log (34 lines) and in 278 KB of `RUST_LOG=trace` stderr; every character spoken |
| Strict K2 to K4 (`m3-k-strict3`, `m3-k4-final`) | K2 p99 0.25 ms, K2s 0.31 ms, K3 0.90 ms; K4 (10,000 switches) `app_lost`, `app_doubled`, `chord_leaked`, `forged_accepted` all 0 |
| R1, R1s, RS (`m3-r1c`) | R1 p99 0.34 ms, R1s 0.38 ms, RS 0 failures |

The numbers come from a Python application and a Python Mutter emulation on a quiet private bus: they bound gorca's own
cost (a few hundred microseconds per echo), not what GTK and Mutter add on the live desktop.

Failing runs kept as evidence (nothing was deleted): `m3-dev3` (SA1 and SA2 failed: the first say-all chunk was replaced in
the speech lane's slot by the second and third, see ADR-0007 changelog); `m3-final` (E1 doubles: the application's insert
signal overtook the keyboard monitor's key event, now a 5 ms hold; S2 lost 176: a selection of more than 1,024 scalars
carries no text, now read from the window); `m3-final3` and `m3-e2` to `m3-e2h` (S2 lost 3 once; E2 1 to 5 of 10,000
missing: a BackSpace's delete signal overtook the key, now a held delete; `m3-e2c` 826 doubles at a 20 to 30 ms pace before
a late key found its insert already spoken). `bench/results/e2e/m3-dev*` are development runs of earlier code.
