# M6 live checklist: GNOME Terminal (VTE)

Run on the real GNOME 48 desktop with `tools/gorca-toggle.sh` (Super+Alt+G); gorca must be the only screen reader.
Specification: `docs/plan/phase-2.md` section M6, ADR-0001 T-1 to T-4, ADR-0008 (the policy is the `ext-vte` extension,
linked natively until the extension host lands), `docs/reports/m6-impl.md` (what was built and measured).
Keys are the NVDA desktop layout. `gorca` = Insert (or KP_Insert with Num Lock off) or Caps Lock. Use GNOME Terminal with
bash (zsh and fish: note anything different). Defaults: `speech.punctuation = "some"`, so a prompt such as
`me@box:~$` is said "me at box colon tilde dollar".

Everything was built against a fake VTE and against a real gnome-terminal-server in a private headless session
(`tests/term/run_real_vte.sh`). Items 2, 4, 5, 6, 9, 11, 12, 13, 15, 19, 22 (with `read -s` instead of `sudo`), 24
(with `seq | less`), 29 and the floods of 18 to 20 are also checked automatically against the real terminal (gate VV,
3 runs). **Not run yet on your desktop**: the whole list, and the first four rows of "Open platform questions".

## Keys and output (30 items)

| # | Step | Expected |
|---|---|---|
| 1 | Alt+Tab to the terminal | the window title, then the line with the cursor (the prompt), once |
| 2 | Type `echo hello` | each character once, from the key press, no echo of the shell's own redraw |
| 3 | Type a space | "space", once |
| 4 | BackSpace twice | the character removed each time |
| 5 | Left, Left | the character the cursor lands on each time (a space says "space") |
| 6 | Home, then End | Home: the first character of the command; End: "blank" |
| 7 | Ctrl+Left, Ctrl+Right (or Alt+B, Alt+F) | the word, as in every editor (unified editing): Ctrl+Left the word the cursor lands on, Ctrl+Right the word just passed, without punctuation (`/usr/local` says `usr`, `local`); a key that moves nothing (Left at the start of the command) speaks the character or word at the cursor |
| 8 | Ctrl+A, Ctrl+E | the first character; "blank" past the end |
| 9 | Enter | `hello`, then the new prompt, in one utterance; the command line is not read again |
| 10 | Enter on an empty prompt | the prompt, once |
| 11 | Up | the recalled command, without the prompt |
| 12 | Up again, then Down, Down | each command; at the bottom "blank" |
| 13 | Type `ec` and press Tab | "echo" (the completed word) |
| 14 | Type `ls /usr/b` and Tab twice | the completion, then the candidates listed in order |
| 15 | Ctrl+U on a typed line | the text that was deleted (several characters), nothing for one character |
| 16 | Ctrl+W | the deleted word |
| 17 | `ls -la /usr/bin` (about 40 lines) | read once, in order, from the top; no repeat |
| 18 | `seq 1 100000` | after the numbers stop: the last lines and the prompt; speech never lags minutes behind |
| 19 | `yes` for ten seconds, then Ctrl+C | speech stays calm while it runs; Ctrl+C silences it at once; then "caret C" (the `^C`) and the prompt |
| 20 | `cat` of a large file, Ctrl+C | as 19; the reader and the other applications stay responsive |
| 21 | `make -j` / `cargo build` | new log lines are read at a steady pace, newest first when it speeds up; never a backlog |
| 22 | `sudo true` | the password prompt is spoken; typed characters are spoken; nothing of them in `journalctl --user`, in gorca's stderr with `RUST_LOG=trace`, or in `gorca+F1` |
| 23 | gorca+F1 right after a password character | it does not repeat the character |
| 24 | `less /etc/services`, Space, `b`, `q` | a page forward and back is read as the new lines at the bottom or top; `q` returns to the prompt |
| 25 | `man ls`, Down arrow in a menu-like program (`mc`, `htop`) | Down reads the row the cursor moves to; `htop`'s once-a-second refresh is silent |
| 26 | `nano file`: type a few letters in the middle of the text | each letter once |
| 27 | Review: numpad 8 (current line), 7 / 9 (previous / next line), 4 / 6 (words), 1 / 3 (characters) | the screen line by line starting at the cursor row; no delay even while `yes` runs in another tab |
| 28 | gorca+Up (current line), twice, three times | the line, spelled, phonetic |
| 29 | Open a second tab (Ctrl+Shift+T), switch with Ctrl+PgUp/PgDn | the tab's title and its cursor line each time |
| 30 | Run `yes` in tab 1, work in tab 2 | no speech from tab 1; tab 2 keys echo at once; `gorca` stays responsive |

Anything that speaks twice for one key, reads a repainted screen as new output, stays silent after Ctrl+C, or lags behind
the terminal is a bug: note the program, the keys and the shell, and run `gorca+F1`. The terminal counters are in the
log when gorca stops (`reader terminal counters`, `RUST_LOG=info`): `typed_echoed` against `typed_explained`,
`output_lines_skipped`, `repaints`, `resync_mismatch`.

## Settings (`gorca.toml`, section `[terminal]`)

| Key | Default | Meaning |
|---|---|---|
| `settle_ms` | 30 | quiet time after the last change before the screen is read (ADR-0001 T-1) |
| `burst_lines` | 40 | more new lines than this in one reading: only the last few are spoken |
| `prompt_markers` | `["$ ", "# ", "% ", "> ", "❯ ", "» "]` | the first one found ends the prompt |
| `prompt_regex` | `""` | a regular expression whose match ends the prompt (wins over the markers); for `PS1` with colours or a multi-part prompt |
| `secret_regex` | `""` | password prompts; empty uses the built-in list (password, passphrase, PIN, token, OTP, verification code) |

If a prompt of yours is not recognised, a recalled command (Up) is read with the prompt in front: set `prompt_regex`.

## Open platform questions (to be answered on the real desktop)

1. **First key after a focus change**: the terminal's focus presentation can come from a snapshot older than the focus.
   gorca grants the application's text events when the first key reaches the terminal. Check that the first character
   typed after Alt+Tab is echoed once and that Up/Left then read correctly.
2. **Trailing blanks**: a real VTE keeps a typed trailing space (`$ cho ` ends in a blank). Check Left at the end of a
   line that ends in a space says "space".
3. **zsh and fish**: right prompts, autosuggestions (grey text after the cursor) and syntax colouring are not special
   cased. Autosuggestion text appears as inserted text: is it read, and is that annoying?
4. **Wide and combining characters** (`ls` of Cyrillic or CJK names, emoji): offsets are scalars of the snapshot;
   check Left/Right over them.
5. **Background tab flood**: ADR-0001 D-5 (per-application deregistration) cannot work with at-spi2-core's atk-bridge
   (the `app` argument never reaches the application); a flooding background terminal is handled by the ingress
   coalescer and `Flooded`. Does a flooding tab 1 ever delay tab 2's echo?
