# M9 live checklist: browse mode in Chrome and Chromium

Run on the real GNOME 48 desktop with `tools/gorca-toggle.sh` (Super+Alt+G), your normal Chrome (or
Chromium), Orca off. Everything on the M7a and M8 checklists applies to Chromium too; this list
covers what is specific to it. The gorca key is Insert (and Caps Lock unless it switches your layout).

Chrome needs no flag: gorca asks it for its page tree itself when it sees the browser (one
read-only call). If Chrome was started before gorca, the page is available a second or so after
you start gorca; switch tabs once if it is not. `chrome://accessibility` shows the mode Chrome is
in ("Web accessibility" on, "Screen reader" off unless gorca runs under the name `orca`, see the
last section).

Compare every row with what NVDA says for the same keys on the same page in Chrome.

## Pages

`tests/web/m7/pages/article.html`, `tests/web/m8/pages/iframes.html`, `anchors.html`, `webapp.html`
(open them with `file://`), a Wikipedia article, a news front page, GitHub, a Gmail-like web app.
Chrome and Chromium (Debian package) both; Chrome stable once per release.

## Reading and text (the doubled-speech check)

| Step | Expected |
|---|---|
| Down / Up on headings, links, labels, paragraphs with links | every word is said **once** ("heading level 1, Gorca article", never "Gorca article, Gorca article") |
| Insert+Down (say all) on an article | one smooth reading, no repeated chunks, no line out of order |
| Left / Right / Ctrl+Left / Ctrl+Right | characters and words of the line, no repeats |

## Entering a page

| Step | Expected |
|---|---|
| Alt+Tab to Chrome | the page title once ("Gorca article, document"; not "... - Google Chrome, Gorca article, document"), "browse mode", the first line; Down then reads the **second** line |
| Open a new page (Enter on a link) | within about a second: the new title and the first line |
| Switch tabs | the title of the new tab, then the line where the cursor was; a tab you never looked at is read after a moment (Chrome builds a background tab's page when it is shown) |
| A very large page (Wikipedia list, a 10 000 row table) | usable within about 2 s; Chrome builds big pages in parts, so the end of the page may be missing for a few seconds |

## In-page links

| Step | Expected |
|---|---|
| Enter on a "Go to section" link (anchors.html) | the cursor lands on the target heading and it is read ("heading level 2, Section two"); Down continues from there |
| Enter on a link to a focusable element | focus and cursor follow |

## Frames

| Step | Expected |
|---|---|
| iframes.html: H, Down through the page | the frame's content is read in order: "Frame form heading", the field, "Srcdoc heading", "Sandboxed text", also for frames below the fold. Right after the page loads the page may scroll to the bottom and back by itself for a moment: this is how gorca makes Chrome build frames that are off screen |
| Tab into the field of the form frame | "focus mode", the field |

## Dialogs and popups

| Step | Expected |
|---|---|
| webapp.html: Compose | "New message, dialog, To, edit" (the dialog's name and role, then the field) |
| Empty trash (alert dialog) | the dialog name and "dialog", then "Cancel, button" |
| A combo box with its list open (Alt+Down on the Combo field in `tests/web/m3b/pages/fields.html`) | the first Escape closes the list and is not "browse mode"; the second returns to browse mode |

## Typing

| Step | Expected |
|---|---|
| Type in a text field and a contenteditable (Gmail compose, GitHub comment) | each key echoed once; Backspace and Delete say the character; arrow keys read characters and lines; no doubled or missing echo, also when typing fast |

## Chrome's own interface (known gaps, report how bad)

Address bar, tab strip, menus, the find bar and download bar are Chrome's own widgets, not page
content. gorca reads them like any other toolkit and they have not been tuned yet: note what is
silent or wrong. The address bar's drop-down list of suggestions is known to have a broken
ancestry in Chrome.

## Under the name `orca` (only if something is missing)

Chrome switches on its "screen reader" mode (more complete page information) when a process named
`orca` runs. gorca does not rename itself by default so that a real Orca next to it keeps working.
If a page behaves differently from NVDA's Chrome (a missing name, a live region that is silent),
start Chrome with `--force-renderer-accessibility` and compare; report the page.
